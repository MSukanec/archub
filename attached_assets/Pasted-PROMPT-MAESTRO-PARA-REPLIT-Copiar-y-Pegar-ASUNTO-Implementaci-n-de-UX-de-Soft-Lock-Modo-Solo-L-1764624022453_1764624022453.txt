ASUNTO: Implementación de UX de "Soft-Lock" (Modo Solo Lectura) para Proyectos y Miembros Excedidos.

CONTEXTO: El backend ya ha ejecutado la lógica de reconciliación de límites. En la base de datos, los proyectos y miembros que exceden el plan actual tienen la columna is_over_limit = true.

OBJETIVO: Implementar la experiencia de usuario en el frontend para manejar estos estados de bloqueo.

Proyectos: Deben ser accesibles pero estar en modo "Solo Lectura" absoluto.

Miembros: Los administradores deben ver quién está suspendido. Los miembros suspendidos deben ser bloqueados al intentar acceder a la organización.

INSTRUCCIONES ESPECÍFICAS POR ÁREA:

ÁREA 1: PROYECTOS (Modo Solo Lectura)
A. En el Listado de Proyectos (Dashboard Principal):

Modifica el componente de la tarjeta de proyecto (ProjectCard o similar).

Si el proyecto tiene is_over_limit: true:

Aplica un estilo visual "apagado" (ej. escala de grises, menor opacidad).

Muestra un icono de candado 🔒 prominente al lado del nombre.

Agrega un pequeño badge o texto que diga "Solo Lectura".

Importante: El clic en la tarjeta DEBE seguir funcionando y llevar al usuario dentro del proyecto.

B. Dentro del Proyecto (El Contexto de Solo Lectura): Cuando un usuario entra a un proyecto que está marcado como is_over_limit: true, toda la interfaz del proyecto debe entrar en modo defensivo.

Actualizar el ProjectContext:

Asegúrate de que el contexto global del proyecto (que usan los componentes hijos) exponga una nueva propiedad booleana: isReadOnly.

Esta propiedad debe ser true si el proyecto actual tiene is_over_limit: true.

Banner de Alerta Global:

En el layout principal del proyecto (probablemente encima de las tabs o debajo del header), si isReadOnly es true, muestra un banner de alerta prominente (color amarillo/naranja).

Texto del banner: "⚠️ MODO SOLO LECTURA. Este proyecto excede los límites de tu plan actual. No puedes realizar cambios. [Botón: Actualizar Plan]"

Deshabilitar Acciones (La parte crítica):

Necesito que revises los componentes principales dentro del dashboard del proyecto (Presupuestos, Tareas, Archivos, etc.).

Cualquier botón o input que implique una acción de escritura (Crear, Editar, Borrar, Subir archivo, Guardar) debe suscribirse al isReadOnly del contexto.

Si isReadOnly es true, estos elementos deben estar deshabilitados (disabled UI) y no permitir la acción.

ÁREA 2: MIEMBROS (Suspensión)
A. Vista del Administrador (Lista de Miembros en Settings):

Modifica la fila del miembro en la tabla de configuración de la organización.

Si un miembro tiene is_over_limit: true:

Muestra un badge rojo evidente que diga "SUSPENDIDO" o "INACTIVO POR PLAN".

Muestra el icono de candado 🔒.

En la parte superior de la página, si hay miembros suspendidos, muestra una alerta indicando la situación y sugiriendo un upgrade.

B. Vista del Miembro Suspendido (El Muro): Qué pasa cuando el usuario "Pepito" (que está suspendido en la Org A) intenta entrar.

Interceptar la Navegación (Auth Guard):

En el componente principal que maneja el layout de la aplicación autenticada o la redirección inicial después del login.

Verifica el estado de la membresía del usuario actual en la organización que intenta acceder.

La Redirección Forzada:

Si su membresía tiene is_over_limit: true, NO le permitas cargar el dashboard de la organización.

Redirígelo inmediatamente a su página de perfil personal, específicamente a la pestaña de organizaciones: /app/profile/organizations (ajusta la ruta si es diferente).

Motivo: Allí podrá ver que está suspendido en la Org A, pero podrá hacer clic para cambiar a su propia organización personal (donde es admin y siempre tiene acceso).

Opcional: Muestra un "toast" de error explicando por qué fue redirigido ("Acceso suspendido a la organización por límites del plan").
