ASUNTO: Implementación de Arquitectura de Componentes de Restricción (Capas Visual y Lógica).

CONTEXTO: Necesitamos estandarizar cómo bloqueamos contenido en la aplicación (por falta de plan, por rol insuficiente, por funcionalidades "coming soon", o por estados de bloqueo contextuales). Vamos a implementar una arquitectura de dos capas para evitar duplicar código visual y separar la lógica de la presentación.

OBJETIVO TÉCNICO: Crear una suite de componentes en TypeScript/React utilizando Tailwind CSS dentro de una nueva carpeta específica.

UBICACIÓN DE LOS ARCHIVOS: Todos los nuevos archivos deben crearse dentro de: src/components/shared/restrictions/

INSTRUCCIONES PASO A PASO PARA EL AGENTE:

PASO 1: Crear la Capa Visual (UI "Tonta") Estos componentes solo se encargan de cómo se VE un bloqueo. No tienen lógica de negocio.

Crea src/components/shared/restrictions/ui/RestrictionOverlay.tsx

Este componente debe mostrarse sobre el contenido (superpuesto).

Debe usar posicionamiento absoluto (absolute inset-0), un fondo semitransparente con desenfoque (bg-background/80 backdrop-blur-sm o similar) y un índice Z alto.

Debe centrar su contenido vertical y horizontalmente.

Props:

icon?: React.ReactNode (Usa un icono de candado de lucide-react por defecto si no se pasa nada).

title: string (Texto principal, ej: "Acceso Restringido").

description?: string (Texto secundario de ayuda).

action?: React.ReactNode (Opcional: para pasar un Botón, ej: "Actualizar Plan").

Usa la tipografía y colores estándar del tema actual.

Crea src/components/shared/restrictions/ui/EmptyStateBlock.tsx

Similar al anterior en contenido (icono, título, descripción, acción), pero NO es superpuesto. Es un bloque normal que ocupa espacio en el flujo del documento. Se usará cuando no hay datos para mostrar y además está bloqueado.

PASO 2: Crear la Capa Lógica (Componentes "Guardianes") Estos componentes envuelven contenido normal y deciden si mostrarlo o si mostrar uno de los componentes de UI del paso 1 en su lugar.

Crea src/components/shared/restrictions/guards/PlanRestricted.tsx

Nota: Si ya existe un componente similar, refactorízalo para que use esta nueva estructura y el RestrictionOverlay.

Este componente debe conectarse al hook de planes (ej. usePlanFeatures) para verificar si la organización actual tiene acceso a la funcionalidad requerida.

Props: featureName: string, children: React.ReactNode.

Lógica: Si tiene acceso, renderiza children. Si no, renderiza RestrictionOverlay con un mensaje genérico de "Mejora tu plan" y un botón de acción.

Crea src/components/shared/restrictions/guards/RoleRestricted.tsx

Este componente sirve para bloquear contenido basado en roles globales (ej. Admin, Fundador) o estados de funcionalidad (Lab, Coming Soon).

Props:

requiredRole: 'admin' | 'founder' | 'lab_user'

children: React.ReactNode

hideCompletely?: boolean (Si es true, no muestra overlay, simplemente retorna null).

Lógica: Debe conectarse al estado del usuario actual (mockéalo por ahora si no existe el hook exacto). Si el usuario no cumple el rol, muestra el RestrictionOverlay con un mensaje adecuado (ej. para 'founder': "Funcionalidad exclusiva para Fundadores. En modo LAB.").

Crea src/components/shared/restrictions/guards/ContextRestricted.tsx

Este es el guardián más simple. La condición de bloqueo se la pasa el componente padre.

Props:

isBlocked: boolean (La condición externa).

blockTitle: string

blockDescription: string

action?: React.ReactNode

children: React.ReactNode

Lógica: Si isBlocked es false, renderiza children. Si es true, renderiza el componente visual apropiado (puedes usar EmptyStateBlock o RestrictionOverlay dependiendo de cómo quieras que se comporte, o incluso aceptar una prop para decidir cuál usar. Por defecto usa EmptyStateBlock para este caso).

RESUMEN DE ENTREGABLES: Al finalizar, deberín existir 5 nuevos archivos TSX estructurados en las subcarpetas ui/ y guards/ dentro de src/components/shared/restrictions/.
