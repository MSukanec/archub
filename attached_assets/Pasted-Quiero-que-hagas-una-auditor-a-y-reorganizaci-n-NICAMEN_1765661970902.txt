CONTEXTO DE ARQUITECTURA

El proyecto ya tiene correctamente definido el Nivel 1:
- components/ui
- components/charts

Eso NO se toca.

Ahora vamos a definir y organizar el NIVEL 2, que es el estándar internacional
usado en dashboards modernos (Linear, Notion, Vercel, etc.).

Nivel 2 = componentes reutilizables que:
- combinan UI y/o charts
- renderizan información visual (cards, métricas, contenedores)
- NO saben nada del dominio (gastos, materiales, proyectos)
- NO consultan datos
- NO hacen cálculos

Ejemplos típicos:
- KPI cards
- Metric cards
- Chart containers
- Summary cards
- Trend cards

---

TAREA 1 — CREAR CARPETA

Crear la carpeta:

components/dashboard

Usar este nombre exactamente. Es un estándar internacional.

---

TAREA 2 — AUDITORÍA

Recorrer el proyecto e identificar componentes existentes que cumplan TODAS estas condiciones:
- Son componentes visuales reutilizables
- Usan componentes de ui/ o charts/
- Reciben datos por props
- No tienen lógica de negocio
- No están ligados a una feature específica

---

TAREA 3 — REORGANIZACIÓN

components/dashboard/
