1. Nueva pestaña / tab

En la página de Gastos Generales, crea una nueva pestaña (tab) que sea la PRIMERA de la sección.
Esta nueva tab se debe llamar:

“Dashboard”

Las otras tabs existentes (listado de gastos, pagos, etc.) deben mantenerse intactas.

2. Propósito de esta nueva página

Esta tab Dashboard de Gastos Generales NO es una tabla.
Su objetivo es:

Dar una visión global del gasto operativo de la organización

Ayudar al usuario a entender qué está pasando

Mostrar KPIs con contexto, no solo números

Usar gráficos claros, simples y reutilizables

3. Modelo de datos (contexto importante)

Existen las siguientes tablas relevantes en Supabase:

general_cost_categories
→ categorías de gastos generales (algunas son del sistema is_system = true, otras de la organización)

general_costs
→ conceptos de gastos generales (Alquiler, Contador, Software, etc.)

general_costs_payments
→ pagos reales de esos gastos

general_cost_payment_allocations
→ prorrateo opcional de un pago a proyectos

También existen vistas:

general_costs_payments_view

general_costs_monthly_summary_view

general_costs_by_category_view

Usa las vistas para el Dashboard, no consultes tablas crudas si no es necesario.

4. KPIs (muy importante)

Los KPIs NO deben ser solo números.

Cada KPI debe:

mostrar el valor principal

mostrar variación o contexto temporal si aplica

incluir una frase explicativa corta (insight)

Ejemplos de KPIs esperados:

Gasto total del período

Promedio mensual

Variación respecto al período anterior

Categoría con mayor impacto

Ten en cuenta todo el trabajo previo de la app sobre:

KPIs explicativos

insights cortos

evitar “números mudos”

5. Gráficos (criterio clave)

Los gráficos que uses en este dashboard:

deben ser agnósticos y reutilizables

NO deben estar acoplados solo a Gastos Generales

Si un gráfico puede reutilizarse en otras secciones:

créalo como componente genérico

colócalo en una carpeta tipo components/charts

Ejemplos de gráficos reutilizables:

Evolución mensual (línea)

Distribución por categoría (torta o barras)

El dashboard solo debe componer estos gráficos, no implementarlos inline.

6. Estilo y consistencia

Respeta el diseño visual existente de la app

Usa los mismos componentes base de cards / layouts

No introduzcas nuevos estilos arbitrarios

Mantén coherencia con el resto del sistema

7. Resumen

Esta nueva tab debe sentirse como:

una vista ejecutiva

clara

explicativa

profesional

NO como una página contable cruda.

Avanza paso a paso y prioriza consistencia sobre velocidad.
