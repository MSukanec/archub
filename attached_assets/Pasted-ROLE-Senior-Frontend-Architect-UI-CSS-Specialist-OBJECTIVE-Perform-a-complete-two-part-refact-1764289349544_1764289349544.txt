ROLE: Senior Frontend Architect & UI/CSS Specialist.

OBJECTIVE: Perform a complete, two-part refactoring of the provided React form component (.tsx). The goal is to align it with the new system architecture standards, making it both architecturally decoupled and visually fluid for different container sizes (modals vs. side panels).

PART 1: ARCHITECTURAL REFACTORING RULES (Separation of Concerns)
THE PROBLEM: Current components are monolithic, mixing heavy form logic (hooks, validation, state) with lightweight view logic in the same component body, often using complex conditionals.

THE MANDATE: You must split the component internally into specialized sub-components within the same file.

Create internal FormPanel component:

Move all heavy logic here: useForm, zodResolver, state variables related to submission, and the <Form {...form}> JSX structure with all inputs.

This panel handles ONLY create and edit modes.

It should accept necessary props like default values or submission handlers.

Create internal ViewPanel component:

Move all read-only display JSX here.

This component must be stateless and lightweight. It receives data via props and displays it cleanly without inputs.

It handles ONLY view mode.

Refactor Main Exported Component (Orchestrator):

The main component (e.g., ClientForm) becomes a simple orchestrator.

It determines the mode.

It conditionally initializes heavy hooks (like useForm) ONLY if needed (i.e., not in view mode), or passes necessary data down.

It switches between rendering <ViewPanel /> or <FormPanel /> based on the mode.

PART 2: LAYOUT REFACTORING RULES (Fluid CSS Grid)
THE PROBLEM: Current form layouts use rigid Tailwind classes (e.g., md:grid-cols-2) that break when rendered inside narrow side panels on desktop screens.

THE MANDATE: Inside the newly created FormPanel (and ViewPanel if applicable), replace rigid grids with intelligent, container-aware CSS Grid patterns.

Apply one of these two rules to every logical group of fields:

RULE A: The "Fluid Multi-Column" Group

Target: Groups containing TWO OR MORE fields intended to sit side-by-side if space allows, but auto-stack in narrow containers.

Action: Wrap these fields in a <div> with this class: className="grid grid-cols-[repeat(auto-fit,minmax(250px,1fr))] gap-4" (Adjust 250px slightly down for small inputs or up for large selects if needed based on context).

RULE B: The "Full Width" Group

Target: Groups containing a SINGLE field that should always occupy full width (e.g., Textarea, main section headers).

Action: Wrap in a <div> with a single-column grid class: className="grid grid-cols-1 gap-4"

EXECUTION WORKFLOW
Analyze Input Code: Identify the parts belonging to form logic versus view logic, and identify rigid layout structures.

Execute Part 1 (Architecture): Extract code into private FormPanel and ViewPanel components and simplify the main orchestrator.

Execute Part 2 (Layout): Scan the JSX inside the new panels. Replace all rigid md:grid-cols-X containers with the appropriate RULE A or RULE B fluid grid structures based on field grouping.

Cleanup: Ensure imports are clean and unused code is removed.

OUTPUT: The complete, refactored .tsx file implementing both architectural separation and fluid layouts.
